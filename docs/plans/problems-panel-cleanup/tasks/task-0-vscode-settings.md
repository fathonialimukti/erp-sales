### Task 0: Hide generated Prisma schema from Problems panel

**Files:**
- Create: `.vscode/settings.json`

**Problem:**
The Prisma VS Code extension loads both `apps/server/src/prisma/schema.prisma` (source) and `apps/server/src/prisma/generated/schema.prisma` (Prisma Client build output, gitignored at `apps/server/.gitignore:13`). Every model/enum/generator/datasource is reported as "already exists" — 40 false errors in the Problems panel.

**Fix:**
Add a workspace `.vscode/settings.json` that hides the generated directory from the file matcher so the extension only sees the source schema. The generated dir is regenerated by `bun prisma generate` — hiding it from the explorer is safe and standard.

**Frozen contract:**
```json
{
  "files.exclude": {
    "**/node_modules": true,
    "**/.turbo": true
  },
  "files.readonlyInclude": {
    "**/prisma/generated/**": true
  },
  "files.watcherExclude": {
    "**/prisma/generated/**": true
  },
  "search.exclude": {
    "**/prisma/generated/**": true
  }
}
```

Notes:
- Do NOT add `"**/prisma/generated/**": true` to `files.exclude` — that hides it from the Prisma extension's own generator view AND the explorer entirely, which is too aggressive. Use `files.readonlyInclude` + `files.watcherExclude` + `search.exclude` to keep it visible-but-quiet.
- If that doesn't clear the Prisma LSP collisions alone, add the Prisma extension setting `"prisma.enabled": true` is already default; instead set `"files.exclude": { "**/prisma/generated/schema.prisma": true }` to hide ONLY the generated schema file (not the whole generated client, which TS imports from).
- Prefer the narrow form: hide just `**/prisma/generated/schema.prisma`.
